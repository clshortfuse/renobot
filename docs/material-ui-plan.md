# Portal Material Design migration plan

- Dense supporter view: use a full-width `mdw-box` list of fluent membership rows; each row uses `mdw-grid` responsive 4/8/12-column spans, compact typography, and a divider rather than a large card. Preserve cursor pagination and role-check state. Desktop fields share one row, narrower containers regroup without custom breakpoints.

- Ko-fi polish: compose expandable settings/history cards with `mdw-card` and `mdw-details`, using the documented summary slot. Keep memberships prominent and forwarding's unavailable status explicit. Move persistence/sync implementation explanations into HTML comments; keep visible copy focused on actions and access. Validate disclosure state and setup submission controls with the sample preview.

- Fluent record components: define `renobot-membership` and `renobot-early-access` through MDW `CustomElement.extend().observe().html.childEvents().register()`. Controllers patch bound state and listen for component action events; remove imperative child-element assembly. Keep server authorization and request handling unchanged. Verify real MDW binding, escaped untrusted text, responsive spans, and action dispatch in the local synthetic preview.

- Component-first follow-up: replace custom status pills and access badges with noninteractive `mdw-label`; use `mdw-box` padding/gap and MDW typography inside outlined cards. Put field labels in the DOM, never positional CSS pseudo-elements. Remove the layered portal reskin CSS, isolate legacy public-page styling, and retain only responsive grid, content inset, text wrapping, and accessibility CSS for the app. Verify stable navigation and readable records at desktop/mobile widths before handoff; leave changes uncommitted for review.

- Rebuild `/app` and both owner/modder dashboards with MDW's documented `mdw-root` → `mdw-nav-drawer` → `mdw-page` → `mdw-pane` → `mdw-top-app-bar` shell. Use `mdw-box`, `mdw-grid`, card surfaces, and MDW controls for a real adaptive application layout, not a centered website card; retain existing IDs, API routes, authorization checks, and text-only rendering.
- Add `@shortfuse/materialdesignweb` as a locked dependency, serve its browser bundle from the same origin under `/assets/`, and keep the strict CSP. Ensure deployment's Nginx/static release path serves it too.
- MDW compatibility: allow runtime style attributes (`style-src-attr 'unsafe-inline'`) and same-origin/data images for its shape masks, but keep stylesheets and scripts same-origin with no inline script permission. Register local SVG aliases before markup upgrades; do not load third-party icon fonts.
- Use Material Design Web cards, buttons, and surface/list patterns across the portal, owner views and public pages. Make early-access review and modder membership readable at mobile and desktop widths with no forced minimum-width table.
- Provide an explicitly local-only preview with synthetic authenticated responses, bound to loopback; never add a preview bypass to the production HTTP server. Preserve the payment-history, approval, import, refresh, pagination, webhook and logout flows. Update static asset and DOM tests, run `npm run check`, and inspect the responsive pages in the browser without interacting with existing user sessions.
